UTXO Chain Lab

Two course assignments joined into one multi-node blockchain in Python: blocks, Merkle trees and proof-of-work consensus from A1, carrying A2's UTXO transactions and Bitcoin Script. It is rebuilt here so you can use it: spend coins, watch the Bitcoin Script stack decide who owns them, seal transactions into a Merkle tree, then mine blocks on three nodes and watch them settle forks by cumulative proof of work. The signatures are real secp256k1 ECDSA, and every hash is computed in your browser.

Spend a coin and watch the six checks

There are no balances. The ledger is a set of unspent coins, each locked by a small script. A transaction names the coins it spends, proves it may unlock them, and creates new coins. verify_transaction runs six checks in order and changes the UTXO set only if all of them pass.

UTXO set

{(txid, vout): {value, script_pubkey}}

Bitcoin keeps no account balances. It keeps a list of coins that have not been spent yet: the UTXO set (unspent transaction outputs). Every coin was created as an output of some earlier transaction, and each one is locked so that only its owner can spend it.

69
  • 69: the coin's value. A coin is always spent whole.
  • Ring color: whose key unlocks it (here Alice's).
  • 8530:1 under a coin: its address in the set. It is output 1 of the transaction whose id starts with 8530.

    03 · from A2 · chain/transaction.py

    What the signature actually covers

    Both hashes come from one canonical serialization: keys sorted at every level, list order kept, no spaces. A signature cannot sign itself, so for input i the signer swaps its script_sig for the locking script of the coin being spent and signs hash256 of those bytes. Change one output by one coin and the message changes, so the signature fails.

      04 · from A1 · chain/merkle.py
      
    Seal the transactions in a Merkle tree
    
      
    Each leaf is a txid. Pairs are hashed with sha256(left_hex + right_hex) until one root is left, and an odd node is paired with a copy of itself. The block header stores only the root, yet any transaction can be proved to be in the block with one sibling hash per level. Click a leaf to see its proof, then edit the transaction.

      05 · from A1 · chain/blockchain.py, chain/node.py
      
    Mine blocks on three nodes and settle forks
    
      
    Each node mines on its own chain, reads its peers' chains and adopts the valid one with the most cumulative work, using the same rule everywhere, so nodes that see the same chains always agree. Mining searches nonces until sha256(index|previous_hash|merkle_root|nonce|timestamp|difficulty) starts with the required number of zero hex digits. Try a mining race, or cut a node off and let it build a shorter but heavier chain.
    
    
    
    
    
      
    Block workA block whose hash needs d leading zero hex digits counts 2^d work (A1's rule). Genesis has d = 0 and counts 1.
    
      
    Fork choiceFollow the tip with the most cumulative work (sum of block work back to genesis), not the longest chain.
    
      
    Deterministic tie-breakEqual work: the tip with the lower block hash wins. Every node breaks the tie the same way, so there is no waiting.

      06 · the combined repository
      
      Where each part lives
      
      
      utxo-chain puts A1's chain around A2's transactions: a block is accepted only if replaying its transactions through the script verifier succeeds against the coins that exist at that height. Every section above runs a JavaScript port of these modules with the same rules and hashes; the genesis block hash on this page equals the Python one.
      
    
      
    
      
      
      blockchain.py

      node.py
